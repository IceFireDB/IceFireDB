                    Sorted sets #

                    15 commands. Scores are 64-bit integers, not doubles — the one difference that changes query results, not just the wire format.

                    Notes #

                    • ⚠ ZINCRBY, ZREMRANGEBYRANK and ZREMRANGEBYSCORE are registered as read commands even though they mutate. Locally that is harmless; in a cluster their effect is not replicated and does not survive a leader change. Until that is fixed: compute scores client-side and write them with ZADD, and remove members with ZREM.
                    • No TTL for sorted sets. There is no ZEXPIRE/ZTTL; clear and recreate the key (ZCLEAR), or keep the expiry bookkeeping in a string key.
                    • Scores parse as int64. A float score such as 1.5 is rejected; WITHSCORES returns integers.
                    • ZRANGEBYSCORE min max is inclusive on both ends; ZREVRANGEBYSCORE max min takes the arguments in reverse order, as in Redis.
                    • ZRANK/ZREVRANK answer null for a missing member, ZSCORE likewise.
                    • All range reads are ordered by score, then by member for equal scores.
