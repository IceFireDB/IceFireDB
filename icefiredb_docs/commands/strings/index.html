                    Notes #

                    • SET clears an existing expiration unless KEEPTTL is given. PX is rounded up to the next second because expirations are stored in whole seconds, so PX 500 keeps the key 1 s and PX 1500 keeps it 2 s — never less than asked.
                    • SET ... NX/XX answers a null bulk when the condition blocks the write, not an error.
                    • There is no string PERSIST: the handler exists but is commented out and not registered. To keep a value and change its lifetime, EXPIRE again or use SET … KEEPTTL.
                    • EXISTS counts keys in the string keyspace only; it will not see a hash with the same name. Use HKEYEXISTS, LKEYEXISTS, SKEYEXISTS for the other types.
                    • DEL deletes the string at those keys, not the same-named hash/list/set.
                    • INCR/DECR on a non-numeric value answer -ERR, like Redis; a missing key is treated as 0.
                    • BITCOUNT/BITPOS accept the optional BYTE/BIT unit as in Redis 7.
                    • Expiry arithmetic uses the Raft clock, so a short TTL can be rejected on a node whose Raft clock lags its local clock. See Compatibility.
                    • TTL is computed against the local wall clock by the storage layer, so replicas can report values that differ by their apply latency.
