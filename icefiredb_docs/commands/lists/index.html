                    Lists #

                    Notes #

                    • LPUSH q a b produces [b, a] — each element is pushed to the head in turn, as in Redis.
                    • LREM KEY count VALUE: count > 0 removes from the head, count < 0 from the tail, count = 0 every occurrence.
                    • LINSERT and LREM are O(n) and are not transactional. The storage layer has no primitive for them, so the handler reads the list, clears it, and rewrites it (restoring the TTL). It happens inside one Raft apply, so no other client observes a partial list, but a backend failure mid-rebuild leaves the list truncated. Do not use them on long lists in a hot path — prefer LTRIM or bounded queues.
                    • There is no LPERSIST: the handler is not registered. LCLEAR/LMCLEAR delete the list and its TTL.
                    • No blocking commands. BLPOP/BRPOP are deliberately not registered: a blocking read inside the Raft apply loop either stalls the log or consumes the queue without a rollback path.
                    • LRANGE with start > stop answers an empty array; negative indexes count from the tail.
