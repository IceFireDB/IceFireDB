                    Ecosystem libraries and components #

                    The engine is one piece. These are the libraries and services around it, all in the same GitHub organisation.

                    Libraries used by the storage drivers #

                    ProjectUsed byWhat it does
                    icefiredb-crdt-kvdriver/crdtCRDT key/value store over libp2p pubsub; merges concurrent writes without coordination
                    icefiredb-ipfs-logdriver/ipfs-log, driver/ipfs-synckvImmutable, operation-based append-only log for distributed systems, stored in IPFS and merged through pubsub
                    IceFireDB/uhaha (fork)the binaryRaft application framework: RESP server, log, snapshots, RAFT/CLUSTER commands
                    IceFireDB/ledisdb (fork)the binaryThe data model: per-type keyspaces, TTLs, encodings

                    Two of these are forked and pinned in go.mod via replace directives. Vendor updates to them are behavioural changes to the engine, so go mod vendor diffs deserve a real review.

                    Services in this repository #

                    IceFireDB-PubSub #

                    Redis PubSub protocol over a libp2p network. Clients keep using SUBSCRIBE/PUBLISH; the server propagates messages across peers, including peers behind NAT.

                    cd IceFireDB-PubSub
make
./bin/IceFireDB-PubSub -c ./config/config.yaml     # proxy.local_port: 16379
redis-cli -p 16379 SUBSCRIBE name
redis-cli -p 16379 PUBLISH name hello

                    Configuration is config/config.yaml: proxy.local_port, p2p.* (discovery id, command topic, mode, host ip/port), pprof_debug, log.level, ip_white_list, cache, ignore_cmd. See IceFireDB-PubSub.

                    IceFireDB-SQLite #

                    MySQL protocol in front of a SQLite file, with statements propagated to peers so every node can answer SQL locally.

                    cd IceFireDB-SQLite
make
./bin/IceFireDB-SQLite -c ./config/config.yaml          # server.addr: ":23306"
mysql -h 127.0.0.1 -P 23306 -u root -p              # password from config userlist

                    IceFireDB-SQLProxy #

                    MySQL protocol proxy that replays statements to a MySQL backend, with separate admin/readonly connection pools and per-tenant users.

                    cd IceFireDB-SQLProxy
make
./bin/IceFireDB-SQLProxy -c ./config/config.yaml        # server.addr: ":33306"

                    IceFireDB-Redis-Proxy #

                    RESP proxy that replicates commands to a single-node or clustered Redis, with optional read/write separation and caching.

                    cd IceFireDB-Redis-Proxy
make
./bin/IceFireDB-Redis-Proxy -c ./config/config.yaml     # proxy.local_port: 16379

                    redhub #

                    A multi-threaded RESP server framework (epoll/raw-epoll based) used by the proxies; useful on its own when you need a fast Redis-protocol front end without the database.

                    Which one do I need? #

                    GoalComponent
                    Redis-compatible KV with Raft and pluggable storageNoSQL engine (this docs section)
                    Decentralized pub/sub between servicesIceFireDB-PubSub
                    SQL semantics on each node, replicatedIceFireDB-SQLite
                    Existing MySQL/Redis made multi-site without rewriting the appSQLProxy / Redis-Proxy
                    Build a RESP front endredhub

                    Not implemented, despite older documentation #

                    • OrbitDB driver — disabled in main.go/flags.go (driver/orbitdb is not built).
                    • NATS integration, vector/AI search, GraphQL endpoint — no code in this tree.
                    • IceFireDB-Proxy as a standalone RESP cluster proxy — the repository ships IceFireDB-Redis-Proxy instead.
