                    Ground rules for contributions #

                    • A handler change ships with a test that fails when the rule it protects is broken; acceptance of two outcomes (err == nil || err == redis.Nil) is not a test.
                    • Every registered command answers to the nine-point audit in COMMAND-AUDIT.md (replication class, determinism, storage behaviour, reply type, bounds, validation-before-write, expiry arithmetic, cursor monotonicity, test coverage).
                    • A behaviour change updates the document that states it: command pages here, COMPATIBILITY.md for divergences, COMMAND-AUDIT.md for the audit ledger.
                    • Commit messages follow the repository convention, e.g. feat(compat): add Redis-compatible SET options, list/set commands and SCAN, and carry a Signed-off-by line (git commit -s).

                    .
├── main.go              # wiring: flags → storage → raft
├── flags.go             # every CLI flag and its validation
├── strings.go           # SET family, counters, bits, expiry
├── hashes.go lists.go set.go sorted_sets.go
├── scan.go              # SCAN/HSCAN/SSCAN/ZSCAN + X* family
├── servers.go           # INFO, FLUSHALL, FLUSHDB
├── snapshot.go          # raft snapshot/restore over driver.IDB
├── observability.go     # /healthz /readyz /metrics
├── server_info.go       # INFO sections
├── driver/              # badger, crdt, hybriddb, ipfs, ipfs-log, ipfs-synckv, oss
├── *_test.go            # unit + integration (+ compat/-tags alltest)
└── docs/superpowers/    # internal plans, not user documentation
