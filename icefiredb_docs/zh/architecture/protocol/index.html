                    协议层 #

                    引擎使用 RESP——Redis 序列化协议——所以任何 Redis 客户端都能直接用，不需要适配层。本页讲协议层在解析字节之外还做了什么。

                    一个 socket，两种协议 #

                    全进程只有一个 TCP 监听（tcp4，地址来自 -a）。到达它上面的是两类连接：

                    1. 客户端连接：应用发来的 RESP。
                    2. 对等连接：节点之间的 Raft 传输。

                    两者由一个嗅探式监听区分：对等节点建立连接时先写一个固定的 magic marker，再跟上集群认证 token（vendor/github.com/tidwall/uhaha 中的 transportMarker）；凡是不以该 marker 开头的，都会被当作 RESP 客户端。这就是 TLS、端口和 --advertise 由数据流量与复制流量共用的原因——也是 --advertise 必须写出对等节点可访问地址的原因。

                    请求处理 #

                    步骤行为
                    解析RESP 数组，另外支持内联（telnet 风格）命令
                    命令名分发前统一转小写——命令名不区分大小写
                    流水线支持：请求按顺序执行，回复按顺序写出
                    连接状态每个连接只有 AUTH 状态；没有按连接隔离的数据库，没有 SELECT
                    内置命令PING、ECHO、QUIT、AUTH、SHUTDOWN 在分发之前由服务器直接应答
                    其它一切分发给命令表（110 条数据命令 + RAFT/CLUSTER/MACHINE/BARRIER/VERSION）

                    未知命令回复 ERR unknown command '<name>'。

                    回复映射 #

                    命令处理器返回 Go 值，RESP 写出器按固定规则机械映射：

                    Go 值RESP
                    nil空批量 $-1
                    []byte / string批量字符串 $n
                    [][]byte / []string / []interface{}数组 *n
                    redcon.SimpleString简单字符串 +…
                    redcon.SimpleInt, int64, int整数 :n
                    error错误 -…

                    值永远不会以简单字符串返回：简单字符串承载不了 \r\n，含 CRLF 的值会破坏数据流。

                    线上的集群语义 #

                    情形回复
                    写命令或只允许主节点执行的读命令被发到从节点-MOVED 0 <advertised-addr>
                    同上，但开启了 --try-errors-TRY <advertised-addr>
                    没有主节点（无多数派）-CLUSTERDOWN …
                    集群感知的客户端询问拓扑CLUSTER SLOTS → 主节点上的单段 0-16383；CLUSTER NODES/INFO

                    MOVED 的槽位永远是 0：没有分片，所以每个键都"属于"唯一的主节点。跟随 MOVED 重定向的客户端最终会落到主节点上，这正是预期行为。

                    错误 #

                    所有错误都是 RESP 错误，并且在客户端库会去识别的位置沿用 Redis 的前缀：

                    前缀含义
                    -ERR …参数错误、语法错误、校验失败
                    -MOVED … / -TRY …重定向到主节点
                    -CLUSTERDOWN …无主节点 / 无多数派
                    -unauthorizedAUTH 缺失或错误
                    -ERR invalid key size / invalid value sizeledis 限额：键 ≤ 1024 B，值 ≤ 1 GiB

                    不会产生 WRONGTYPE——见 兼容性。

                    协议层里没有的东西 #

                    没有 MULTI/EXEC，没有 SUBSCRIBE，没有 WATCH，也没有内联 SELECT。发布/订阅在另一个二进制里（ IceFireDB-PubSub）。
