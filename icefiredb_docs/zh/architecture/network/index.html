                    网络层 #

                    系统里存在两套彼此独立的网络，解决的是不同问题。读 IceFireDB 相关内容时，把两者混为一谈是最常见的架构错误。

                    站内网络站间网络
                    用途一份一致的数据副本跨站点 / 跨地域复制
                    技术Raft（hashicorp/raft）libp2p + pubsub（crdt、ipfs-log、ipfs-synckv 驱动）
                    拓扑主节点 + 投票者，需要多数派对等网络，无主节点，最终一致
                    配置方式-a、-j、--advertise、--raft-backend、--auth、TLS--servicename、--nettopic、--datatopic
                    启用方式始终启用仅在 P2P 存储驱动下启用

                    常见部署是每个站点跑一个 Raft 集群（站内强一致），每个站点再有一个节点使用 P2P 存储驱动在站点之间交换数据（跨站最终一致）。引擎不会替你合并这两层——它们是彼此独立的分层，而 P2P 层是驱动的属性，不是服务器的属性。

                    站内：Raft #

                    • 每个节点只监听一个 socket。对等连接用 transport marker 加认证 token 表明身份，所以复制流量和客户端流量共用同一个端口和同一份 TLS 证书。
                    • Raft 日志与稳定存储位于 <data-dir>/IceFireDB/<node-id>/store/，格式为 leveldb（默认）或 bolt（--raft-backend）。
                    • --advertise 设置其它节点保存的本节点地址。不设置时使用绑定的地址，在 NAT 后面或容器里这是错的。
                    • 加入集群：-j <addr>（节点自己加入），或在主节点上执行 RAFT SERVER ADD id address。
                    • 快照：由 Raft 层生成，通过 writeSnapshot 写入 snapshots/<id>/state.bin；被快照覆盖的日志会被截断。
                    • 时钟：Raft 通过内部复制的 TICK 命令驱动机器时钟（默认每 200 ms 一次），使依赖时间的命令在各副本间保持一致。--localtime 用本地时间源替换远程时间源，更快，也更有风险。

                    站间：P2P 驱动 #

                    crdt、ipfs-log 和 ipfs-synckv 驱动会在存储层里打开一个 libp2p host：

                    驱动发现 / 传输数据模型身份
                    crdtlibp2p DHT + pubsub，带命名空间基于本地 Badger/LevelDB 的 icefiredb-crdt-kv CRDT map--servicename + --nettopic
                    ipfs-logIPFS pubsub + icefiredb-ipfs-log只追加的操作日志，按对等节点合并--ipfs-log-dbname
                    ipfs-synckvIPFS 节点 + ipfs-log，可选 AES-256带版本的 KV，以 IPFS 为事实来源，本地镜像--ipfs-synckv-key（用于加密）

                    运维层面的后果：

                    • 三个 flag 必须一致，能互相看见的节点之间才连得上。--servicename、--nettopic 和 --datatopic 是汇合点：不一致会静默地形成两个互不相干的网络，而不是报错。
                    • 没有多数派，没有主节点。 写命令在本地成功，等对等节点连上后再传播；被网络分区的节点会继续接受写入，重新加入时再合并（CRDT 语义），这与上面的 Raft 层是完全不同的约定。
                    • 必须能访问 IPFS：ipfs、ipfs-synckv 和 ipfs-log 通过 --ipfs-endpoint（http://localhost:5001，即 API 端口）访问 IPFS。:8080 上的网关不是 API 端点。
                    • 对等节点在网络层是受信任的。 这张网依赖共享的发现名称，没有逐节点的授权。见 安全。

                    端口协议用途

                    11002HTTP/healthz、/readyz、/metrics（--metrics）
                    26063HTTPpprof（--pprof）

                    网络层不做什么 #

                    • 不集成 service mesh；除 libp2p 发现之外没有基于 gossip 的成员管理。
                    • 不保证跨站一致性：P2P 层是最终一致的，Raft 层只在单个集群内。
                    • 不做多集群联邦：两个 Raft 集群不会自动合并。
