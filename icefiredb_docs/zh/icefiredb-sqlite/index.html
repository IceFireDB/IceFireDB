                    IceFireDB-SQLite #

                    一个 MySQL 协议服务器，它把数据存放在本地 SQLite 文件中，并把语句传播给对等节点，因此每个节点 都能针对自己那份副本回答 SQL 查询。

                    cd IceFireDB-SQLite
make                                 # → bin/IceFireDB-SQLite
./bin/IceFireDB-SQLite -c ./config/config.yaml

mysql -h 127.0.0.1 -P 23306 -u root -p    # password from userlist in the config

                    它是什么 #

                    属性取值
                    协议MySQL 线上协议（MySQL 客户端、驱动、ORM）
                    存储SQLite 文件，sqlite.filename
                    复制语句经 libp2p 在对等节点之间传播
                    监听server.addr，默认 :23306
                    二进制bin/IceFireDB-SQLite（-c <config.yaml>）

                    配置（config/config.yaml） #

                    配置项含义文件中的默认值
                    server.addrMySQL 监听地址":23306"
                    sqlite.filenameSQLite 数据库文件db/sqlite.db
                    debug.enable / .portpprof 服务器false / 17878
                    p2p.enableP2P 复制true
                    p2p.service_discovery_id会合名，必须与其他节点一致p2p_sqlite_service
                    p2p.service_command_topic命令频道p2p_sqlite_service_topic
                    p2p.service_discover_modeadvertise 或 announceadvertise
                    p2p.node_host_ip / node_host_port对等节点应当拨号的地址127.0.0.1 / 0
                    userlist租户账号：user + passwordroot / 123456

                    运维要点 #

                    • 示例密码就是 123456。 在暴露端口之前先改掉 userlist —— MySQL 客户端会很乐意用这个密码 连上来。
                    • 语句会在对等节点上重放，所以非确定性的 SQL（NOW()、RAND()、UUID()）可能在不同节点之间产生 分歧。请让语句保持确定性，或者接受这种漂移。
                    • 每个节点在自己的 SQLite 文件里保存一份完整副本；没有分片，也没有选主。
                    • 表结构变更加和其他语句一样传播：请在安静的时刻执行，不要与写入并发。

                    与 NoSQL 引擎的关系 #

                    不同的二进制、不同的协议、不同的一致性故事：没有 Raft，没有 RESP，没有共享的存储驱动。当应用本身就是 SQL 形态、目标就是每个节点本地读时用它；当你需要 Raft 一致性和 RESP 时，用 NoSQL 引擎。
