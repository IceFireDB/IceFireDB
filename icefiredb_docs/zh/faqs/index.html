                    常见问题 #

                    它能替代 Redis 吗？ #

                    它使用 RESP 协议，实现了 110 条命令，其中大多数与 Redis 语义一致，因此 Redis 客户端无需改动即可连接。 但它不是可以直接顶替 Redis 的实现：没有 WRONGTYPE，没有 SELECT，没有事务，没有阻塞命令，键名 上限为 1024 字节，还有三条有序集合命令不参与复制。迁移任何你在意的数据之前，请先读 兼容性。

                    支持哪些命令？ #

                    110 条数据命令，外加 RAFT/CLUSTER/MACHINE/BARRIER/AUTH 系统命令。完整清单在 命令参考，每种数据类型一页，附回复类型与限额。

                    为什么 INFO memory 会失败？ #

                    因为在这个引擎里 INFO 不接受参数。请用 INFO，再从回复里解析出 # Mem 段。见 可观测性。

                    为什么没有 WRONGTYPE 错误？ #

                    因为存储模型为每种数据类型保留一个键空间，所以一个键名可以同时存放字符串、哈希和列表，而类型不符的 命令是在该类型自己的视图上执行。同样也没有 TYPE 命令，所以类型安全是应用自己的责任。这一点由 compat_test.go 锁定。

                    为什么我在 Go/Python 里的 HSCAN 会报解析错误？ #

                    因为 HSCAN/SSCAN/ZSCAN 用最后一个字段名或成员名作为游标，而不是数字，而各客户端的类型化 助手会把游标强制转成 int。请改用通用命令接口（Do、execute_command）。SCAN 自己的游标是不 透明的 base64，配合 Scan 风格的助手没有问题。见 扫描。

                    如何配置它？ #

                    只能用命令行 flag —— 没有配置文件。--storage-backend、-a、-n、-d、-j、--auth、 --tls-cert/--tls-key、--metrics、--pprof，以及各驱动的 flag。带默认值的完整清单见 配置。

                    --hot-cache-size 是真实存在的 flag 吗？ #

                    不是。-h 会把它打印出来，但它并没有被注册，所以传它会直接报错，缓存容量仍是驱动默认的 1024 MB。见 会打印出来但没有接线的 flag。

                    该用哪个存储后端？ #

                    除非你有别的理由，否则用 goleveldb。本地写入更重时用 badger，读密集工作集用 hybriddb，数据 必须比主机活得更久时用 oss，多站点 P2P 用 ipfs-synckv/crdt。ipfs 驱动目前不能当作通用后端 使用。见 存储驱动。

                    如何扩展读能力？ #

                    增加节点并用 --openreads 运行，让从节点提供读服务，或者把协议代理指向从节点。没有分片：每个节点 持有全量数据集。见 集群。

                    如何备份和恢复？ #

                    先 RAFT SNAPSHOT NOW，再用 RAFT SNAPSHOT FILE <id> 取文件，或者复制一个已静默的节点目录。恢复时 用 --restore <file> 导入一个全新的数据目录，然后让其他节点重新加入。细节与注意事项见 运维。

                    能把 badger 的备份恢复到 goleveldb 节点吗？ #

                    快照可以（state.bin 是与后端无关的键/值流）。复制出来的数据目录不行 —— main.db/ 与具体后端 绑定，而且永远不要为已有的数据目录更改 --storage-backend。

                    为什么从节点返回了 -MOVED 0 <addr>？ #

                    因为不带 --openreads 时，从节点拒绝读请求并重定向到主节点。所有键都使用槽位 0；没有分片。加上 --try-errors 后，同样的回复会变成 -TRY。

                    我在集群里的写入去哪了？ #

                    如果是 ZINCRBY、ZREMRANGEBYRANK 或 ZREMRANGEBYSCORE，那就没去哪：这三条被注册成读命令，所以 只修改你发送到的那一个节点。请改用带算好分值的 ZADD，删除用 ZREM。

                    为什么不能用超过 1024 字节的键？ #

                    因为 ledis 把键、字段以及集合/有序集合成员都限制在 1 KiB（值最大可到 1 GiB）。这是存储层的限制， 不是策略。请保持键紧凑，并把长标识符在客户端做哈希。

                    生产环境可用吗？ #

                    引擎以 1.0.0-rc.1 发布。本地后端（goleveldb、badger、hybriddb）、Raft 复制、快照、TLS/认证 和可观测性都有 CI 覆盖（包括崩溃恢复、故障转移和分区测试）。去中心化驱动则参差不齐：ipfs-synckv 有测试，crdt/ipfs-log 在本仓库里没有单元测试，ipfs 无法把值原样存取回来。风险请自行承担。

                    有认证吗？是按用户区分的吗？ #

                    只有一个共享 token（--auth 或 ICEFIREDB_AUTH），每条连接都必须提供，由所有节点共用。没有用户、 角色，也没有按命令的权限。请把它和 TLS 一起用。见 安全。

                    支持事务、pub/sub、流或 SQL 吗？ #

                    这个二进制不支持。MULTI/EXEC、pub/sub、流和 SQL 都没有实现；pub/sub 是独立的二进制 （ IceFireDB-PubSub），SQL 支持在 IceFireDB-SQLite/ SQLProxy 里。

                    采用什么许可证？ #

                    引擎是 Apache 2.0，PubSub 组件是 MIT。见各自目录下的 LICENSE。

                    我在哪里报 bug？ #

                    github.com/IceFireDB/IceFireDB/issues。附上一份针对 make run 的复现步骤，再加上 INFO 输出和所用的后端，分诊最快。
