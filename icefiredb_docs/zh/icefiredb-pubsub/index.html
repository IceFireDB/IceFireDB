                    IceFireDB-PubSub #

                    运行在 libp2p 网络之上的 Redis PubSub 协议：客户端照旧使用 SUBSCRIBE/PUBLISH，而消息在各个 节点之间跨越 NAT 和地域传输，不再局限在单个 Redis 实例内部。

                    cd IceFireDB-PubSub
make                                   # → bin/IceFireDB-PubSub
./bin/IceFireDB-PubSub -c ./config/config.yaml

redis-cli -p 16379 SUBSCRIBE name      # terminal 1
redis-cli -p 16379 PUBLISH name hello  # terminal 2 (any node in the mesh)

                    它是什么 #

                    属性取值
                    协议Redis RESP —— SUBSCRIBE、UNSUBSCRIBE、PSUBSCRIBE、PUBLISH
                    节点间传输libp2p pubsub（Kademlia DHT + IPFS 网络发现）
                    本地监听proxy.local_port，默认 16379
                    二进制bin/IceFireDB-PubSub（-c <config.yaml>）
                    状态不做持久化：这是消息总线，不是数据库

                    配置（config/config.yaml） #

                    配置项含义文件中的默认值
                    proxy.local_portRESP 监听端口16379
                    proxy.enable_mtls协议代理之间的双向 TLSfalse
                    p2p.enable是否开启 libp2p 网络true
                    p2p.service_discovery_id会合名（rendezvous）—— 各对等节点之间必须一致p2p_redis_proxy_service_test
                    p2p.service_command_topic网络内部的命令频道p2p_redis_proxy_service_topic_test
                    p2p.service_discover_modeadvertise 或 announceadvertise
                    p2p.node_host_ip / node_host_port对等节点应当使用的地址（0 表示任意端口）127.0.0.1 / 0
                    pprof_debug.enable / .port/debug/pprof 服务器true / 16060
                    log.leveldebug、info、warn、errordebug
                    ip_white_list.enable / .list客户端 IP 白名单true / 回环地址条目
                    cache.enable / .max_items_size / .default_expiration（毫秒）/ .cleanup_interval（秒）消息缓存true / 2048 / 5000 / 120
                    ignore_cmd.enable / .cmd_list丢弃选定的命令false / []

                    在真实部署里真的会咬人的几点：

                    • 发现 id 和命令 topic 就是网络身份。把示例配置照抄过去却不改它们，你的集群就会和所有同样照抄的 人处在同一个网络里。
                    • 示例配置里 pprof_debug 是开启的，并在 16060 上监听。请把它关掉，或者绑定到回环地址并加上防火墙。
                    • IP 白名单默认开启，内容里只有 127.0.0.1，所以在你不把它的地址加进去之前，任何远程客户端都会被拒绝。

                    它不做什么 #

                    • 没有消息持久化，没有重放，没有消费者组，没有流。
                    • 没有跨网络的桥接：两个不同的 service_discovery_id 就是两个互不相干的世界。
                    • 它不属于 NoSQL 引擎的命令面 —— 引擎根本没有 SUBSCRIBE。

                    它适合放在哪里 #

                    当你的 web2 客户端已经在通过 Redis 发布消息，而你又想让这条消息总线跨站点延伸、却不想重写它们时，就用 它。如果你需要投递保证，请搭配一个真正的队列；PubSub 按设计就是尽力而为。
