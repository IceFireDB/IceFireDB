                    扫描 #

                    8 条命令，分两族，两套不同的游标契约。把它们搞混是使用本引擎时最常见的集成错误。

                    命令读写语法返回示例 → 回复
                    SCANRSCAN cursor [MATCH glob] [COUNT n] [TYPE type]array [cursor, keys]，游标为 0 表示结束SCAN 0 MATCH user:* COUNT 100 → [cursor, [user:1, user:2]]
                    HSCANRHSCAN KEY cursor [MATCH glob] [COUNT n]array [cursor, [field, value, ...]]HSCAN user:1 0 COUNT 10 → [0, [name, ada]]
                    SSCANRSSCAN KEY cursor [MATCH glob] [COUNT n]array [cursor, [member, ...]]SSCAN tags 0 → [0, [go]]
                    ZSCANRZSCAN KEY cursor [MATCH glob] [COUNT n]array [cursor, [member, score, ...]]ZSCAN board 0 → [0, [ada, 105]]
                    XSCANRXSCAN type cursor [MATCH regex] [COUNT n] [ASC|DESC]array [cursor, keys]，空游标表示结束XSCAN KV "" COUNT 5 → [key:5, [...]]
                    XHSCANRXHSCAN KEY cursor [MATCH regex] [COUNT n] [ASC|DESC]array [cursor, [field, value, ...]]XHSCAN user:1 "" COUNT 5 → [name, [name, ada]]
                    XSSCANRXSSCAN KEY cursor [MATCH regex] [COUNT n] [ASC|DESC]array [cursor, [member, ...]]XSSCAN tags "" → [go, [go]]
                    XZSCANRXZSCAN KEY cursor [MATCH regex] [COUNT n] [ASC|DESC]array [cursor, [member, score, ...]]XZSCAN board "" → [ada, [ada, 105]]

                    Redis 族 #

                    SCAN / HSCAN / SSCAN / ZSCAN 沿用 Redis 的形态，但不沿用 Redis 的游标编码。

                    • 从游标 0 开始；当回复中的游标为 0 时遍历结束。
                    • SCAN 的游标是一个不透明的 base64 字符串，携带五个子游标，每个键空间一个（string、hash、list、set、zset）。它不是数字，也不是键偏移。
                    • HSCAN / SSCAN / ZSCAN 把最后一个字段名或成员名作为游标返回。后果：
                      • 名字恰好是 0 的字段会与结束标记冲突。
                      • 把游标当整数解析的客户端助手（例如 go-redis 的类型化 HScan）会拒绝它。请使用通用命令接口：redis-cli、Do("hscan", …)、execute_command。
                    • MATCH 接受 Redis glob（*、?、[abc]、\\ 转义），会被转成正则，由处理器在有限的一页上应用。
                    • SCAN 支持 TYPE string|hash|list|set|zset；未知类型返回空结果。
                    • 省略时 COUNT 默认为 10。

                    X 族 #

                    XSCAN / XHSCAN / XSSCAN / XZSCAN 是引擎原生的扫描：

                    • 从空游标 "" 开始；当返回空游标时遍历结束。
                    • MATCH 是正则表达式，不是 glob，会传给存储层。
                    • ASC / DESC 选择方向（DESC 用 RevScan 遍历）。
                    • XSCAN 的第一个参数是类型名：KV、HASH、LIST、SET、ZSET（不区分大小写；其他任何值都会报 invalid key type 错误）。

                    两族通用的规则 #

                    • COUNT 只是提示，上限 10000。它限制的是内存分配，而不是返回的条目数。
                    • 一页可能返回空结果，但游标仍然前进。 绝不要在短页或空页上停下；要循环到游标为 0（Redis 族）或 ""（X 族）。
                    • 扫描不取快照：遍历期间新增或删除的键可能出现，也可能不出现。这与 Redis 给出的保证相同。
                    • 两族都是读命令，因此在从节点上需要 --openreads（或重定向到主节点）。

                    循环写法 #

                    # Redis family — go-redis's typed HScan does not work; use the generic API
cursor = 0
while True:
    cursor, keys = r.execute_command("SCAN", cursor, "MATCH", "user:*", "COUNT", 500)
    for k in keys:
        ...
    if cursor == b"0" or cursor == "0":
        break

# X family — empty cursor terminates
cursor = ""
while True:
    cursor, items = r.execute_command("XSCAN", "HASH", cursor, "MATCH", "^user:", "COUNT", 500)
    for k in items:
        ...
    if not cursor:
        break

                    # redis-cli drives the cursor for you on SCAN
redis-cli -p 11001 --scan --pattern 'user:*' | head
