                    说明 #

                    • LPUSH q a b 得到 [b, a] —— 每个元素依次压入头部，与 Redis 一致。
                    • LREM KEY count VALUE：count > 0 从头部删，count < 0 从尾部删，count = 0 删除每一处出现。
                    • LINSERT 和 LREM 是 O(n)，而且不是事务性的。 存储层没有它们的原语，因此处理器会读取列表、清空它，再重新写入（并恢复 TTL）。整个过程发生在同一次 Raft apply 内，所以其他客户端观察不到半成品列表，但中途后端失败会留下被截断的列表。不要在热路径的长列表上使用它们 —— 优先用 LTRIM 或有界队列。
                    • 没有 LPERSIST：处理器未注册。LCLEAR/LMCLEAR 删除整个列表及其 TTL。
                    • 没有阻塞命令。 BLPOP/BRPOP 是刻意不注册的：在 Raft apply 循环里做阻塞读，要么卡住日志，要么在没有回滚路径的情况下消费掉队列。
                    • LRANGE 在 start > stop 时返回空数组；负索引从尾部计。
