                    构建与测试 #

                    构建 #

                    make localbuild     # bin/IceFireDB for the host platform
make run            # go run . (development)
make run_dev        # same, for a dev setup
make clean          # remove bin/ and installed copies

                    发布与交叉编译目标确实存在（make all、make release、make build-linux-*），但在迭代代码时请用 run/localbuild——发布矩阵每次调用会构建五个 GOOS/GOARCH 变体。

                    二进制里嵌入了自己的 git revision 和构建时间：

                    go build -ldflags "-X main.BuildVersion=$(git rev-parse --short HEAD) -X main.BuildDate=$(date '+%F %T')" -o bin/IceFireDB .

                    -h 会显示版本，并且在设置了 BuildVersion 时把它写进 banner。

                    测试套件 #

                    命令跑什么
                    make test / go test ./...单元测试，遵循 DRIVER
                    DRIVER=goleveldb make test-compatRESP 兼容性套件，-tags alltest
                    make test-integration先构建二进制，再跑崩溃恢复和多节点 Raft 故障切换测试（-tags integration）
                    make test-partition基于 Docker 的脑裂测试：3 个节点，主节点被切断网络（-tags partition）
                    make soak对 3 节点集群施加持续负载；SOAK_DURATION、SOAK_WORKERS、SOAK_CHAOS=1

                    DRIVER 选择测试所针对的存储驱动（Makefile 的默认值是 badger）：

                    DRIVER=badger     make test
DRIVER=goleveldb  make test-compat
DRIVER=hybriddb   go test ./driver/hybriddb/...

                    部分驱动的测试需要先有基础设施才能跑：

                    驱动前置条件
                    ossS3 兼容端点；CI 会启动 LocalStack 并设置 OSS_TEST_ENDPOINT
                    ipfs、ipfs-synckv在 --ipfs-endpoint 处的 IPFS daemon
                    crdt、ipfs-log测试节点之间的 libp2p 连通性

                    CI 跑什么 #

                    .github/workflows/test.yml 对每个驱动各跑一次 alltest 套件——oss、ipfs、ipfs-synckv、 goleveldb、crdt、ipfs-log、badger、hybriddb——另外还跑各驱动专属的包和 SQLite 套件。oss 任务使用 LocalStack（MinIO 的公共镜像已经无法匿名拉取）。

                    .github/workflows/build.yml 构建五个发布目标，这样只在 amd64 上能编译通过的改动就混不过去。

                    两个 workflow 都锁定模块声明的工具链：go 1.26.0 加 toolchain go1.27.3，CI 用 Go 1.27.3。 本地 go 低于该版本会在模块的 toolchain 指令处失败，而不是在代码处失败。

                    为一条命令写测试 #

                    //go:build alltest

package main

import (
	"context"
	"testing"
)

func TestMyCommandContract(t *testing.T) {
	c := getTestConn()              // helper used by the compat suite
	ctx := context.Background()

	// 1. the happy path
	// 2. the boundary the handler is supposed to enforce
	// 3. the reply type, not just the value
	_ = c
	_ = ctx
}

                    凡是把"与 Redis 的偏差"固定下来的东西，都应该放进兼容性套件，因为 compat_test.go 正是这些偏差所指向的那份文档。

                    值得手动跑一遍的静态检查 #

                    go vet ./...
gofmt -l .            # expect no output outside vendor/
go mod tidy && go mod vendor   # after touching go.mod

                    注意 go mod vendor 会重写 vendor/ 目录树——Raft/RESP 层和 ledis 都在里面，所以 vendor 更新是一次代码审查，不是走形式。
