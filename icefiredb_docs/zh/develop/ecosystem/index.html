                    生态库与组件 #

                    引擎只是其中一块。下面是它周围的库和服务，全部在同一个 GitHub 组织下。

                    存储驱动使用的库 #

                    项目使用者作用
                    icefiredb-crdt-kvdriver/crdt基于 libp2p pubsub 的 CRDT 键/值存储；无需协调即可合并并发写入
                    icefiredb-ipfs-logdriver/ipfs-log、driver/ipfs-synckv面向分布式系统的不可变、基于操作的只追加日志，存于 IPFS，并通过 pubsub 合并
                    IceFireDB/uhaha（fork）本二进制Raft 应用框架：RESP 服务器、日志、快照、RAFT/CLUSTER 命令
                    IceFireDB/ledisdb（fork）本二进制数据模型：按类型的键空间、TTL、编码

                    其中两个是 fork，通过 replace 指令固定在 go.mod 里。更新它们的 vendor 代码就是改变引擎的行为，所以 go mod vendor 产生的 diff 值得认真审查。

                    本仓库中的服务 #

                    IceFireDB-PubSub #

                    在 libp2p 网络上提供 Redis 发布/订阅协议。客户端照旧使用 SUBSCRIBE/PUBLISH；服务器把消息在对等节点之间传播，包括 NAT 后面的节点。

                    cd IceFireDB-PubSub
make
./bin/IceFireDB-PubSub -c ./config/config.yaml     # proxy.local_port: 16379
redis-cli -p 16379 SUBSCRIBE name
redis-cli -p 16379 PUBLISH name hello

                    配置在 config/config.yaml：proxy.local_port、p2p.*（发现 id、命令 topic、模式、host ip/port）、 pprof_debug、log.level、ip_white_list、cache、ignore_cmd。见 IceFireDB-PubSub。

                    IceFireDB-SQLite #

                    在 SQLite 文件前面提供 MySQL 协议，并把语句传播到对等节点，使每个节点都能在本地应答 SQL。

                    cd IceFireDB-SQLite
make
./bin/IceFireDB-SQLite -c ./config/config.yaml          # server.addr: ":23306"
mysql -h 127.0.0.1 -P 23306 -u root -p              # password from config userlist

                    IceFireDB-SQLProxy #

                    把语句重放到 MySQL 后端的 MySQL 协议代理，管理池与只读连接池分开，用户按租户划分。

                    cd IceFireDB-SQLProxy
make
./bin/IceFireDB-SQLProxy -c ./config/config.yaml        # server.addr: ":33306"

                    IceFireDB-Redis-Proxy #

                    把命令复制到单节点或集群 Redis 的 RESP 代理，可选读写分离与缓存。

                    cd IceFireDB-Redis-Proxy
make
./bin/IceFireDB-Redis-Proxy -c ./config/config.yaml     # proxy.local_port: 16379

                    redhub #

                    多线程 RESP 服务器框架（基于 epoll/raw-epoll），各个代理都在用它；当你需要一个快速的 Redis 协议前端而不需要数据库时，它也可以单独使用。

                    我需要哪一个？ #

                    目标组件
                    带 Raft 与可插拔存储的 Redis 兼容 KVNoSQL 引擎（即本套文档）
                    服务之间的去中心化发布/订阅IceFireDB-PubSub
                    每个节点本地具备 SQL 语义并能复制IceFireDB-SQLite
                    不改应用就让现有 MySQL/Redis 多地部署SQLProxy / Redis-Proxy
                    自建 RESP 前端redhub

                    没有实现的功能（尽管旧文档里有） #

                    • OrbitDB 驱动 —— 在 main.go/flags.go 里被禁用（driver/orbitdb 不参与构建）。
                    • NATS 集成、向量/AI 检索、GraphQL 端点 —— 这棵代码树里没有对应代码。
                    • IceFireDB-Proxy 作为独立的 RESP 集群代理 —— 仓库里实际提供的是 IceFireDB-Redis-Proxy。
