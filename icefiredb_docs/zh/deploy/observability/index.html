                    可观测性 #

                    有三种方式能看到节点在做什么：HTTP 端点、INFO 命令和 pprof。三者都需要显式开启。

                    HTTP 端点 #

                    ./bin/IceFireDB --metrics --metrics-addr 127.0.0.1:11002 -d /var/lib/icefiredb
                    路径响应用途
                    /healthz只要进程还活着就返回 200 ok存活探针
                    /readyz存储驱动初始化完成后返回 200 ready；在此之前返回 503 not ready就绪探针 / 上线门禁
                    /metricsPrometheus 文本格式抓取

                    服务端是一个普通的 http.Server，ReadHeaderTimeout 为 5 秒；它没有认证，所以留在回环地址或私有 网卡上（见 安全）。

                    暴露的指标 #

                    注册表不是全局那个——它注册的正好是：

                    指标类型含义
                    icefiredb_connected_clientsgauge当前打开的 RESP 连接数
                    go_*collectorGo 运行时（goroutine、GC、memstats……）
                    process_*collector进程 CPU、RSS、FD、启动时间

                    没有 Raft 指标，没有按命令的计数器，也没有延迟直方图。命令和存储的计数器改放在 INFO 里（见 下文）。抓取间隔和告警应当依赖 up、icefiredb_connected_clients 以及容器层面的信号。

                    # prometheus.yml
scrape_configs:
  - job_name: icefiredb
    static_configs:
      - targets: ["127.0.0.1:11002"]

                    INFO #

                    INFO 不接受参数——INFO memory 是参数错误，这点与 Redis 不同。它回复一个 bulk string，包含 五个段，然后是为每个注册了额外指标的存储驱动追加的一段。

                    # Server
os:linux
arch:amd64
process_id:1
addr:127.0.0.1:11001
http_addr:
readonly:false
goroutine_num:38
gomaxprocs:8
thread_num:12
cgo_call_num:0
resp_client_num:1
ledisdb_version:...
# Store
name:goleveldb
get:0
get_missing:0
put:0
delete:0
get_total_time:0s
iter:0
iter_seek:0
iter_close:0
batch_commit:0
batch_commit_total_time:0s
# Mem
mem_alloc:... mem_sys:... mem_heap_alloc:... mem_head_objects:...
# GC
gc_last_time:... gc_num:... gc_pause_total:... gc_pause_history:...
                    段字段说明
                    Serveros, arch, process_id, addr, http_addr, readonly, goroutine_num, gomaxprocs, thread_num, cgo_call_num, resp_client_num, ledisdb_versionaddr 是配置的绑定地址；readonly 来自 ledis 配置，在这里始终是 false
                    Storename, get, get_missing, put, delete, get_total_time, iter, iter_seek, iter_close, batch_commit, batch_commit_total_time计数器是进程级的，重启后清零
                    Memmem_alloc, mem_sys, mem_looksups, mem_mallocs, mem_frees, mem_total, mem_heap_alloc, mem_heap_sys, mem_head_idle, mem_head_inuse, mem_head_released, mem_head_objects人类可读的大小（1.234G）
                    GCgc_last_time, gc_num, gc_pause_total, gc_pause_history最近五次暂停
                    驱动段见下文仅适用于实现了 Metrics() 的后端

                    由 main.go 追加的驱动段：

                    • hybriddb：read_operations、write_operations、delete_operations、bytes_read、 bytes_written、errors、uptime、closed。
                    • ipfs、ipfs-synckv、oss：一个 hybriddb cache 段（这个标题在驱动里是复制粘贴的），带 Ristretto 计数器——used_cost、cost_added、cost_evicted、hits、misses、ratio、 keys_added、keys_evicted、keys_updated、gets_kept、gets_dropped、sets_dropped、 sets_rejected。

                    INFO 是一条读命令：由你请求的节点服务，从不复制，从节点在本地回复。

                    pprof #

                    ./bin/IceFireDB --pprof --pprof-addr 127.0.0.1:26063 -d /var/lib/icefiredb
go tool pprof http://127.0.0.1:26063/debug/pprof/heap

                    标准 net/http/pprof 处理器：/debug/pprof/{profile,heap,goroutine,block,mutex,trace}。与 /metrics 同样的注意事项——无认证，默认在回环地址上。

                    集群状态 #

                    集群和 Raft 状态以命令而不是指标的形式暴露：

                    redis-cli -p 11001 RAFT LEADER       # advertise address of the current leader
redis-cli -p 11001 RAFT INFO         # raft state/term/index snapshot
redis-cli -p 11001 RAFT SERVER LIST  # id, address, leader flag per member
redis-cli -p 11001 CLUSTER INFO      # cluster_state:ok/fail, cluster_known_nodes, cluster_size
redis-cli -p 11001 CLUSTER NODES     # redis-cluster-shaped node lines
redis-cli -p 11001 MACHINE           # now / uptime / boottime from the Raft clock

                    MACHINE HUMAN 以 RFC3339 时间戳和 Go duration 返回同样的值。见 系统命令。

                    该对什么告警 #

                    信号位置含义
                    /readyz 非 200HTTP 探针存储没有初始化——节点不应接收流量
                    up{job="icefiredb"}Prometheus节点或它的指标端点已消失
                    -CLUSTERDOWN、-MOVED 风暴你的客户端指标写路径找不到主节点；检查多数派
                    resp_client_num 增长INFO Server客户端连接池里的连接泄漏
                    get_missing / put 比例INFO Store读缺失占主导——缓存命中率或数据集问题
                    gc_pause_total 斜率INFO GC分配压力，通常是大的回复或大的 pipeline
