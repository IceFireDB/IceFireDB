                    配置 #

                    NoSQL 引擎没有配置文件。每一项设置都是一个命令行 flag，在启动时由 flags.go 解析一次。（工作 目录中的 .env 文件同样会被加载 —— 见 环境变量。）

                    ./bin/IceFireDB -h     # prints the usage block below

                    基本选项 #

                    Flag含义默认值
                    -a addr绑定地址（host:port）127.0.0.1:11001
                    -n id节点 ID —— 同时也是 Raft 服务器 ID 和数据子目录名1
                    -d dir数据目录data
                    -j addr要加入的集群的主节点地址(空 —— 引导新集群)
                    -l level日志级别：debug、verb、info、warn、silentinfo
                    -h打印用法并退出—

                    -n 是标识符，不是端口。端口来自 -a。两个节点可以共享 -d，因为每个节点都写入 <dir>/IceFireDB/<node-id>/；但两个节点不能共享同一个节点 ID。

                    安全选项 #

                    Flag含义默认值
                    --auth token集群认证令牌，由所有节点和所有客户端共享(空 —— 认证关闭)
                    --tls-cert pathTLS 证书（PEM）(空)
                    --tls-key pathTLS 私钥（PEM）(空)

                    --tls-cert 与 --tls-key 必须成对提供；只提供其中一个会导致启动错误。--auth 也可以从 ICEFIREDB_AUTH 读取，两者都设置时以命令行为准。完整行为，包括该令牌保护什么、不保护什么，见 安全。

                    集群与网络选项 #

                    Flag含义默认值
                    --advertise addr其他节点访问本节点时应使用的地址(网络绑定地址)
                    --openreads允许从节点提供读命令服务（数据可能陈旧）false
                    --nosync跳过每次写入的磁盘同步（更快，但断电会丢失最近的写入）false
                    --localtime从本地机器取 Raft 时钟，而不是用网络时间源false
                    --try-errors非主节点读返回 -TRY 而不是 -MOVED，并禁用 CLUSTER 命令false
                    --restore path从快照文件引导一个全新的单节点集群(空)
                    --init-run-quit初始化引导状态后退出false
                    --raft-backend nameRaft 日志存储：leveldb 或 boltleveldb

                    --advertise 必须包含端口；不带端口（或端口非数字）的取值会在启动时被拒绝。--restore 不能与 -j 组合使用，并且在数据目录已存在时会被忽略。见 集群与 运维。

                    存储选项 #

                    Flag含义默认值
                    --storage-backend nameledis 数据模型之下的 KV 驱动goleveldb
                    --ipfs-endpoint urlIPFS API 端点（HTTP API，不是网关）http://localhost:5001
                    --ipfs-synckv-key keyipfs-synckv 驱动的加密密钥（AES-256：32 字节）(空 —— 不加密)
                    --ipfs-log-dbname name由 ipfs-log 各节点共享的数据库名／标识ifdb-event-kv-ipfs-log
                    --oss-endpoint url兼容 S3 的端点http://localhost:9000
                    --oss-ak keyAccess key驱动默认值中的占位值
                    --oss-sk secretSecret key驱动默认值中的占位值

                    支持的 --storage-backend 取值：goleveldb、badger、hybriddb、oss、ipfs、ipfs-synckv、 crdt、ipfs-log。leveldb（cgo 驱动）与 orbitdb 没有编译进二进制。各驱动具体保证什么，见 存储驱动。

                    P2P 选项（去中心化驱动） #

                    这些选项配置 crdt 与 ipfs-log 驱动所使用的 libp2p 层。它们对本地存储驱动和对象存储驱动没有 影响。

                    Flag含义默认值
                    --servicename name服务发现标识icefiredb
                    --nettopic topic节点发现 pubsub 频道icefiredb-net
                    --datatopic topic数据同步 pubsub 频道icefiredb-data

                    只有这三项全部一致时，节点之间才会交换数据。在一个运行中的集群里改动它们，会把集群割裂开。

                    可观测性选项 #

                    Flag含义默认值
                    --metrics启用 HTTP 端点 /healthz、/readyz、/metricsfalse
                    --metrics-addr addr这些端点的绑定地址127.0.0.1:11002
                    --pprof启用 pprof 性能分析服务器false
                    --pprof-addr addrpprof 绑定地址127.0.0.1:26063

                    两个服务器默认关闭，并且是刻意绑定在回环地址上的。见 可观测性。

                    诊断选项 #

                    Flag含义默认值
                    -t 1..9测试辅助：由一位数字推导出地址与节点 ID（节点 1 引导，其余节点加入它）(未设置)
                    --debug已注册，但目前未被使用false

                    -t 只是搭建本地集群的便利手段；它不属于本文档记录的接口，并且会改写 -a、-n 与 -j。

                    环境变量 #

                    变量由谁读取作用
                    ICEFIREDB_AUTHflags.go命令行未给出 --auth 时作为集群认证令牌
                    IPFS_LOG_DBNAMEdriver/ipfs-log在打开时覆盖 ipfs-log 的数据库名

                    二进制在启动时还会调用 godotenv.Load()，所以工作目录中的 .env 文件可以设置上面这些变量。请把 密钥放在 ICEFIREDB_AUTH 或 .env 里，而不是放在命令行上 —— 在大多数系统上进程列表是全局可读的。

                    会打印出来但没有接线的 flag #

                    -h 会为 --hot-cache-size 打印一行 Store options。该 flag 并没有注册，也没有任何效果： oss、ipfs 与 ipfs-synckv 驱动的热缓存容量就是驱动默认的 1024 MB，设置在 driver/*/db.go 中。--pubsub-id 同理：它出现在用法文本里，但随被禁用的 OrbitDB 驱动一起被注释掉了。

                    传入未注册的 flag，会让 Go 的 flag 包以 flag provided but not defined 终止，所以这一点会立刻 暴露出来，而不是被静默忽略。

                    --debug 是相反的情况：它已注册，但没有任何代码读取它设置的变量，因此它同样不改变任何行为。

                    常用组合 #

                    本地开发，单节点

                    ./bin/IceFireDB -a 127.0.0.1:11001 -n 1 -d ./data -l debug --nosync

                    三节点集群，启用认证，指标绑定在回环地址

                    export ICEFIREDB_AUTH=change-me
./bin/IceFireDB -n 1 -a 0.0.0.0:11001 --advertise 10.0.0.1:11001 -d /var/lib/icefiredb --metrics
./bin/IceFireDB -n 2 -a 0.0.0.0:11001 --advertise 10.0.0.2:11001 -d /var/lib/icefiredb --metrics -j 10.0.0.1:11001
./bin/IceFireDB -n 3 -a 0.0.0.0:11001 --advertise 10.0.0.3:11001 -d /var/lib/icefiredb --metrics -j 10.0.0.1:11001

                    Badger、TLS 与从节点读

                    ./bin/IceFireDB --storage-backend badger --tls-cert ./cert.pem --tls-key ./key.pem \
  --openreads -a 0.0.0.0:11001 -d /var/lib/icefiredb

                    去中心化 CRDT 驱动

                    ./bin/IceFireDB --storage-backend crdt \
  --servicename my-service --nettopic my-net --datatopic my-data \
  -d /var/lib/icefiredb
