                    快速开始 #

                    本页带你从一次干净的代码检出走到运行中的节点，然后是三节点集群，最后落在两件从 Redis 转过来的人 最先遇到、也最容易意外的事上。

                    前置条件 #

                    • Go 1.27.3+。模块声明 go 1.26.0 并带 toolchain go1.27.3，CI 用 Go 1.27.3 构建与测试。
                    • make（可选 —— 每个 target 都只是一层薄薄的 go build）。
                    • 一个 RESP 客户端：除类型化 scan 辅助工具外（见 兼容性），redis-cli 足以应付一切。

                    1. 构建 #

                    git clone https://github.com/IceFireDB/IceFireDB.git
cd IceFireDB
make localbuild          # → ./bin/IceFireDB

                    make localbuild 就是 go build -ldflags "-X main.BuildVersion=<git sha> -X main.BuildDate=<date>"。 make all 交叉编译整套发布矩阵（linux amd64/arm64/armv5/armv6/armv7）—— 发布时有用，开发时不必； make run 与 make run_dev 只是 go run .。

                    2. 运行单个节点 #

                    ./bin/IceFireDB -a 127.0.0.1:11001 -n 1 -d ./data -l info

                    这一行把每个默认值都显式写了出来：绑定地址是 127.0.0.1:11001，节点 ID 是 1，数据目录是 data，日志级别是 info。二进制会打印一段 banner，然后是 start with Storage Engine: goleveldb， 接着是日志中的 Raft 部分。

                    状态写入每个节点各自的目录，因此多个节点可以共享同一个 -d：

                    data/
└── IceFireDB/
    └── 1/
        ├── main.db/      # the ledis storage (driver-dependent)
        ├── store/        # Raft log + stable store (leveldb or bolt, see --raft-backend)
        └── snapshots/    # Raft snapshots, one directory per snapshot ID

                    3. 第一批命令 #

                    redis-cli -p 11001

127.0.0.1:11001> SET user:1 '{"name":"ada"}' EX 300
OK
127.0.0.1:11001> GET user:1
"{\"name\":\"ada\"}"
127.0.0.1:11001> TTL user:1
(integer) 299
127.0.0.1:11001> HSET user:1 name ada
(integer) 1
127.0.0.1:11001> HGET user:1 name
"ada"
127.0.0.1:11001> INFO
$...

                    注意第 4 步：同一个键 user:1 同时持有一个字符串和一个哈希。这不是 bug —— 见 第 5 步。

                    4. 三节点集群 #

                    节点 1 是引导节点；节点 2 和 3 用 -j 加入它。每个节点保留自己的 -d（也可以共享父目录，节点 ID 会把它们区分开）。

                    # node 1 — bootstrap
./bin/IceFireDB -a 127.0.0.1:11001 -n 1 -d ./data &

# node 2 — join
./bin/IceFireDB -a 127.0.0.1:11002 -n 2 -d ./data -j 127.0.0.1:11001 &

# node 3 — join
./bin/IceFireDB -a 127.0.0.1:11003 -n 3 -d ./data -j 127.0.0.1:11001 &

                    从任意节点检查拓扑：

                    redis-cli -p 11001 CLUSTER INFO
redis-cli -p 11001 CLUSTER NODES
redis-cli -p 11001 RAFT LEADER

                    向主节点写入，从从节点读取：

                    redis-cli -p 11001 SET cluster:smoke ok      # leader → OK
redis-cli -p 11002 GET cluster:smoke         # follower → -MOVED error unless --openreads

                    没有 --openreads 的从节点会返回重定向错误，而不是陈旧数据；需要从节点读时再加上 --openreads。 成员变更、快照与故障处理见 集群。

                    5. 两件与 Redis 不同的事 #

                    1. 没有 WRONGTYPE。 引擎为每种数据类型维护独立的键空间，所以 SET k v 和 HSET k f x 可以 同时成功；对错误类型执行的命令会读取该类型自己的（可能为空的）视图，而不是报错。如果你的应用 依赖 WRONGTYPE 来保证类型安全，请在应用层检查类型。
                    2. Scan 游标是不透明的，而对 HSCAN 来说游标就是名字。 把游标当整数解析的客户端辅助工具（例如 go-redis 的类型化 HScan）不可用；请改用通用命令 API。

                    这两点，加上另外八处偏差，都在 兼容性中。
