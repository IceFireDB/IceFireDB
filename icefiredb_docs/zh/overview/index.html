                    IceFireDB 是什么 #

                    IceFireDB 是一个连接 web2 与 web3 存储的数据库基础设施项目。本站记录的是位于仓库根目录、用于 构建 IceFireDB 二进制的那个组件 —— NoSQL 引擎：一个兼容 Redis 的服务器，其写入经 Raft 日志 复制，数据存放在可插拔的 KV 驱动中。

                    这两个维度彼此独立，整个设计就是如此：

                    • 一致性维度 —— 一个站点（或一个可用区）内部的 Raft 集群。主节点接受写入，从节点重放日志， --openreads 允许从节点提供读服务。
                    • 存储维度 —— ledis 数据模型之后的一个 store.driver.IDB 实现。它可以是本地 LSM 引擎、对象 存储，或 P2P 复制存储。命令层并不知道具体是哪一个。

                    其余的一切 —— RESP 接口面、按类型划分的键空间、过期时间、快照 —— 都叠加在这两个维度之上。

                    redis-cli / any RESP client
            │
            ▼
   RESP server (uhaha + redcon)          ← pipelining, TLS, AUTH, CLUSTER/RAFT commands
            │
            ▼
   Raft log (hashicorp/raft)             ← write commands are replayed on every replica
            │
            ▼
   command handlers (strings/hashes/lists/sets/zsets/scan)
            │
            ▼
   ledis data model  (one keyspace per type)
            │
            ▼
   driver.IDB  →  goleveldb | badger | hybriddb | oss | ipfs | ipfs-synckv | crdt | ipfs-log

                    产品地图 #

                    组件它是什么运行位置
                    NoSQL 引擎（本文档章节）RESP 服务器、Raft 复制、可插拔 KV 存储仓库根目录，二进制 IceFireDB
                    IceFireDB-PubSub运行在 libp2p 网络之上的 Redis PubSub 协议IceFireDB-PubSub/
                    IceFireDB-SQLite面向 P2P 同步的 SQLite 文件的 MySQL 协议IceFireDB-SQLite/
                    IceFireDB-SQLProxy把语句复制到 MySQL 后端的 MySQL 代理IceFireDB-SQLProxy/
                    IceFireDB-Redis-Proxy把命令复制到 Redis 后端的 RESP 代理IceFireDB-Redis-Proxy/

                    NoSQL 引擎是本站唯一作为数据库引擎来记录的组件；四个代理属于中间件，各自在自己的配置文件中记录。
