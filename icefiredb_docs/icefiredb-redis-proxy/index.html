                    IceFireDB-Redis-Proxy #

                    A RESP proxy in front of Redis (single node or cluster) that replays commands to the other agents in the mesh. Existing Redis applications get multi-site synchronisation without switching databases.

                    cd IceFireDB-Redis-Proxy
make                                   # → bin/IceFireDB-Redis-Proxy
./bin/IceFireDB-Redis-Proxy -c ./config/config.yaml

redis-cli -p 16379 SET k v

                    What it is #

                    PropertyValue
                    ProtocolRedis RESP on both sides
                    Backendredisdb.type: node or cluster, redisdb.start_nodes
                    ReplicationCommands propagated between agents over libp2p
                    Listenerproxy.local_port, default 16379
                    Binarybin/IceFireDB-Redis-Proxy (-c <config.yaml>)

                    Operational notes #

                    • redisdb.start_nodes must point at a reachable backend before clients connect; the proxy is not a database and has no storage of its own.
                    • Commands are replayed on peers: non-deterministic ones (SPOP, INCRBYFLOAT, anything using server time, EVAL with math.random) will diverge across sites. Prefer deterministic operations, or keep those keys in one site.
                    • The cache in front of the backend defaults to enabled with a 5 s expiration — read-after-write from a different client can be stale for up to that window. Disable cache.enable when you need strict reads.
                    • pprof_debug is on in the sample config (16060); disable it outside development.
                    • Same discovery-id caveat as PubSub: two deployments with the same id share a mesh.
