                    What IceFireDB is #

                    IceFireDB is a database infrastructure project that bridges web2 and web3 storage. This site documents the component that lives in the repository root and builds the IceFireDB binary — the NoSQL engine: a Redis-compatible server whose writes are replicated through a Raft log and whose data lives in a pluggable KV driver.

                    The two axes are independent, and that is the whole design:

                    • Consistency axis — a Raft cluster inside one site (or one availability zone). A leader accepts writes, followers replay the log, --openreads lets followers serve reads.
                    • Storage axis — a store.driver.IDB implementation behind the ledis data model. It can be a local LSM engine, an object store, or a P2P replicated store. The command layer does not know which.

                    Everything else — the RESP surface, the per-type keyspaces, expiration, snapshots — is layered on top of those two.

                    redis-cli / any RESP client
            │
            ▼
   RESP server (uhaha + redcon)          ← pipelining, TLS, AUTH, CLUSTER/RAFT commands
            │
            ▼
   Raft log (hashicorp/raft)             ← write commands are replayed on every replica
            │
            ▼
   command handlers (strings/hashes/lists/sets/zsets/scan)
            │
            ▼
   ledis data model  (one keyspace per type)
            │
            ▼
   driver.IDB  →  goleveldb | badger | hybriddb | oss | ipfs | ipfs-synckv | crdt | ipfs-log

                    The NoSQL engine is the only component documented as a database engine here; the four proxies are middleware and are documented with their own configuration files.
